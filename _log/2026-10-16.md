# E2E suite, two styling bugs it found, and the 1.0.7 release

The monorepo session (now "Pikari Gutenberg plugins") passed on Steve's request for a Playwright suite modelled on modals #163. Building it turned up two styling bugs. Both shipped in 1.0.7 the same day. Steve made every scope, merge and release call in this session.

## Decisions and why

- **Skip baselines of broken renders.** A baseline of an unstyled card would lock the bug in. Steve chose to flag it and skip those baselines. Once 1.0.7 fixed both bugs, the six skipped baselines were captured and reviewed.
- **The contact-link fix is CSS only.** The markup stays `__contact-link`, so any theme CSS that targets it keeps working. The address rule is scoped to a direct child of the card, which leaves the carousel slide on the single page untouched.
- **One enqueue helper for every entry point.** `Template::enqueue_card_assets()` serves the single page, the block and the shortcode, so the CSS filters behave the same everywhere. OSC replaces its CSS through `pikari_team_card_css_file`, so its embeds now get its own CSS.
- **Defer the enqueue to `wp_enqueue_scripts` in block themes.** The first version enqueued while the block template rendered. That printed card.css before the global and layout styles, and the constrained layout's `max-width` then won on equal specificity. The single-page visual baseline caught it on the first run: the card grew from 400px to the content width.
- **Guard on `registered`, not `enqueued`.** The WordPress-core review caught that a theme's documented dequeue would be undone by the next card on the page. One limit remains: in a classic theme, a card on an ordinary page enqueues after the hook, so it can't be dequeued there. The `pikari_team_card_css_file` → `false` opt-out is documented instead of adding new API.
- **Test the CSS in Vitest, not only in e2e.** CI doesn't run Playwright, so `card.test.js` loads card.css into jsdom and checks computed styles. jsdom does apply the stylesheet cascade.
- **#57 merged with `skip-changelog`.** A `feature/` branch name would otherwise have bumped main to 1.1.0 for a change that only adds tests.

## Surprises

- **The contact-link bug was six months old.** The original standalone template used `__link`. The Card_Renderer refactor (b940e70) renamed it, and `/card/` has rendered unstyled ever since 17381ad. Nothing caught it until there was a visual test.
- **wp-env opcache served mutated PHP after it was restored.** The mutation runner restored files with `mv`, which leaves an older mtime. During the next mutation, the previous one was still live. That made `/card/` look like it leaked a protected member's details. I caught it by curling with clean code: `touch` the file after restoring it, then wait 2s or more.
- **All 30 tests passed on the first run.** Too clean to trust, so I ran mutation checks; 6 of 6 were caught. A test that only checks scrolling would have passed with `aria-selected` broken, so it has its own assertion.
- **OSC wasn't affected the way we assumed.** Its `/card/` and `/team-member/` pages use the `osc-2024` theme's own templates. Only a card block or shortcode on an OSC page would have been unstyled.
- **The auto-mode classifier blocked merges twice** until Steve approved them in his own words. It also blocked a local commit on the docs branch for the same reason.
