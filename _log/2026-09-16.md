# JS unit tests for every script, and a stale release todo

## Context

The monorepo session reported a gap. Since #38 made Test a required check on `main`, pikari-team's JS step had passed with nothing to run: `passWithNoTests: true`, and not one `*.test.js`. Before replying, I confirmed each claim in the code.

## Decisions and why

- **Tests went in by priority, not all at once.** #39 covered the card-page scripts (`carousel.js`, `sw-register.js`) first, because v1 targets Classic Editor sites and those scripts ship on the standalone card page. Steve then asked for the block editor files to be tested straight away instead of filed as a todo (#40).
- **No new dependencies.** Testing Library isn't installed, and the `@wordpress/*` editor packages are WordPress externals, not installed either. Instead, `jest.mock( …, { virtual: true } )` stand-ins render native inputs, selects and buttons, and components mount with `createRoot` and `act`. Adding packages would have changed `package.json` and the lock files, getting the dependencies label and lock-sync checks, for a PR that only adds tests.
- **Deliberate breaks replaced the TDD red step.** The code already existed, so a new test passing proves nothing. Each suite was checked by breaking the source one change at a time and restoring it after: 18 of 18 caught for #39, 20 of 21 for #40. I chose the breaks, so they lean toward what the tests check.
- **Assertions check what the code saves, not how the fakes render.** Examples: the object passed to `setMeta`, `setAttributes( { postId: 9 } )`, the `useEntityRecords` query. The 17 field→meta-key pairs are literals checked by hand against `Post_Type::META_FIELDS`, because the REST API silently drops unregistered keys.
- **Both PRs got `skip-changelog`.** The autolabeler doesn't recognise the `test/` branch prefix, so an unlabelled PR falls through to a patch and would trigger a version bump for tests alone.
- **The plugin's session-log rules were followed.** Its `CLAUDE.md` says `_specs/roadmap.md` and `_log/YYYY-MM-DD.md`; the global rules say `_log/roadmap.md` with `-sNN` names. No roadmap existed, so I created `_specs/roadmap.md` with only the items I could check against today's code.

## Surprises

- `sw-register.js` and `carousel.js` are pasted into the same inline `<script>`, so an error thrown by the service-worker code also stops the carousel. That's why the "browser without service worker support" test exists.
- The `'card-default'` fallback for the template dropdown makes no visible difference: with no value, a native select shows its first option, which is already Default. It was the only break no test caught, and none could.
- The panel "Company" and the field "Company" share a label, so looking the field up by `aria-label` returned the panel. The fix was in the fake, which now renders panel titles as headings.
- ESLint's settings for test files don't define `globalThis`; use `global`.
- Todo #488 ("release v1.0.2") was stale. v1.0.2 was published 2026-09-12, and the 1.0.3 bump is merged. I proposed it done and Steve closed it.
- Dependabot auto-merge was failing with "GitHub Actions is not permitted to approve pull requests". Steve enabled the repo setting, and #37 then merged. No open Dependabot PR in modals or query-filter shows the same failure; I didn't look further.
- The route list in `CLAUDE.md` doesn't match `Template.php`: it says `/manifest.json` and `/sw.js`, but the rules are `/manifest/` and `/service-worker/`.
